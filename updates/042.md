## Journey and Troubleshooting

### 1. Verification of Port Allocation Logic
- **Problem**: We planned to add dynamic TCP port checks to prevent port collisions at the OS level.
- **Analysis**: We inspected the source code in `apps/agent-infra/orchestrator/process.go` and found that `PortAllocator.Allocate()` already incorporated an OS-level listener check (`isPortOSAvailable`) attempting to bind `net.Listen("tcp", ...)` temporarily.
- **Solution**: We verified the existing implementation is robust, avoiding redundant changes, and documented this behavior clearly in the new `STRUCTURE.md`.

### 2. Lack of Automatic Self-Healing for Crashed Instances
- **Problem**: When subprocesses crashed, they transitioned to the `StatusTerminated` state. However, the orchestrator only ran reconciliation when triggered by user REST requests (like Deploy or Scale) or metrics autoscaler actions. There was no continuous monitor ensuring that dead replicas were replaced.
- **Analysis**: We identified the need for a continuous scheduler reconciler loop, similar to Kubernetes controllers, to provide robust service availability.
- **Solution**: We added `StartReconcilerLoop` in the scheduler. It fetches all registered deployment names and runs a non-blocking `Reconcile` pass every 5 seconds. If an instance has terminated unexpectedly, the scheduler automatically releases its port, frees its node resources, and provisions a new running replica.
