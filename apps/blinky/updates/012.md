# Blinky Click-Through Overlay Hit Testing Fix

Date: 2026-07-22

Step 1: Explain action  
Diagnosed click-through edge case where UI controls became unclickable when Click-Through mode was toggled on. During Tailwind CSS refactoring, component wrapper class names (`top-bar`, `assistant-panel`, `logo-bar-container`) were omitted, causing `event.target.closest(...)` in `App.tsx`'s mouse hit testing logic to fail and lock Electron in ignore-mouse-events pass-through mode.

Step 2: Explain modification  
- Updated `src/ui/components/TopControlBar.tsx`: Added `top-bar` selector class to header container.
- Updated `src/ui/components/AssistantPanel.tsx`: Added `assistant-panel` selector class to panel container.
- Updated `src/ui/components/LogoBar.tsx`: Added `logo-bar-container` selector class to logo pill container.
- Updated `src/ui/App.tsx`: Enhanced mouse hover hit testing logic to verify button and input element hover states.

Step 3: Explain outcome  
Verified compilation using `npx tsc --noEmit`. Electron window mouse event ignore state now correctly toggles `setIgnoreMouseEvents(false)` whenever hovering over top bar, assistant panel, logo bar, or interactive UI controls, fixing unclickable overlay edge cases.
